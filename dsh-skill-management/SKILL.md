# DeepSeek Harness 技能（Skill）系统管理指南

> **核心概念**：DSH 的"长期记忆"本质上就是【技能系统】。把知识写成 SKILL.md 放入技能目录，DSH 会自动发现并在后续会话中按需加载。本指南教你管理这些技能文件。

---

## 给智能体（Agent）的快速指引

当用户在任何会话中要求"查看技能/查看记忆/列出技能"时，请按下述流程操作：

1. **列出所有技能目录**：
   ```powershell
   Get-ChildItem "$env:USERPROFILE\.dsh\skills" -Directory | Select-Object -ExpandProperty Name
   ```
2. **同时列出平铺文件**（`<名称>.md` 也算技能）：
   ```powershell
   Get-ChildItem "$env:USERPROFILE\.dsh\skills" -File | Select-Object -ExpandProperty Name
   ```
3. **逐个读取技能正文**：用 `read` 工具打开 `<技能目录>\SKILL.md` 或 `<名称>.md`，向用户展示每个技能的：
   - 技能名（`name`）
   - 描述（`description`）
   - 核心要点（正文摘要）
   - 存储路径
4. **模型侧目录**（catalog）已自动包含所有技能的名称与描述，也可按上述文件方式核对。
5. **增删改技能**：写入/删除技能目录在会话工作区之外，会触发沙箱权限确认，需向用户说明并请求批准。

**示例输出格式**（每个技能一条）：
```
• 技能名：<name>
  描述：<description>
  存储：C:\Users\19781\.dsh\skills\<name>\SKILL.md
  要点：<正文摘要/目录>
```

## 一、概述：技能（Skill）是什么

DeepSeek Harness（DSH）的跨会话长期能力核心机制是【技能（Skill）系统】。

| 类型 | 生命周期 | 说明 |
|------|----------|------|
| 普通对话（短期） | 当前会话 | 只存在于当前上下文，会话结束即消失 |
| 技能（长期） | 跨会话持久化 | 以 SKILL.md 文件存于磁盘，每次新会话自动扫描并注入模型目录 |

**一句话解释**：技能 = 带元信息（名字/描述/适用场景）的 Markdown 指令文件，放在特定目录里，DSH 自动发现，模型按需加载。

> **为什么以前叫 "Memory"？**  
> 早期把技能系统通俗地称为"长期记忆"，但这容易和普通对话记忆混淆。实际上 DSH 并没有独立的 "Memory 模块"——技能系统就是长期记忆的唯一实现方式。因此本指南使用"技能"这一准确术语。

**其他相关但不同的机制**（对比见第八节）：
- **工作区普通文件**：可写，但不会自动加载，需用户提醒模型读取。
- **Persona（人格/全局指令）**：注入所有会话的系统提示，影响面更广。
- **Goal 工具**：同一会话内的长任务目标跟踪，不跨会话。
- **会话记录（`~/.dsh/sessions`）**：历史对话存档，用于回溯，不是"记忆指令"。

## 二、存储位置

DSH 配置文件根目录（Harness Home）：
```
DSH_HOME 环境变量 = C:\Users\19781\.dsh
（未设置时默认 ~/.dsh）
```

技能扫描根目录（按优先级从高到低）：

| 优先级 | 级别 | 路径 | 说明 |
|--------|------|------|------|
| Rank 1 | 项目级 | `<项目根>/.dsh/skills` | 项目根 = 最近含 `.git` 的祖先目录 |
| Rank 2 | 项目级 | `<项目根>/.agents/skills` | 兼容路径 |
| Rank 3 | 自定义 | `customSkillDirs` 配置项 | 用户自定义目录 |
| Rank 4 | 用户级 | `<DSH_HOME>/skills` | **即 `C:\Users\19781\.dsh\skills`，推荐放通用技能** |
| Rank 5 | 用户级 | `<agentsHome>/skills` | `~/.agents/skills`，默认不存在 |

- **用户级目录**对所有会话、所有项目生效，是放"通用知识"的首选位置。
- **项目级目录**只对该项目生效，适合放项目专属规范。
- 相同技能名在不同位置时，**rank 高者优先**。

DSH 用户数据目录中的其他内容：
```
C:\Users\19781\.dsh\sessions\     会话记录存档（JSONL）
C:\Users\19781\.dsh\storages\     各类持久化存储
C:\Users\19781\.dsh\settings.yaml 设置
C:\Users\19781\.dsh\profiles\     配置文件
```

> ⚠️ 技能目录在会话工作区之外。模型在工作区外的写操作会被沙箱拦截，需要弹窗批准（权限升级）后才能写入。

## 三、技能文件格式（SKILL.md）

技能支持两种文件形式（不支持下钻嵌套目录）：

1. **目录包（推荐）**：`<技能名>/SKILL.md` —— 可附带引用资源
2. **平铺**：`<技能名>.md` —— 单文件

### 文件格式 = YAML frontmatter + Markdown 正文

```yaml
---
name: my-skill-name                # 必填，必须 kebab-case（小写+连字符）
description: 一句话描述该技能何时使用   # 必填，会出现在模型目录摘要里
whenToUse: 更详细的适用场景说明     # 可选
metadata:                          # 可选，自定义键值
  created: 2026-08-18
  author: your-name
disable-model-invocation: false    # 可选：true 则模型目录中隐藏
user-invocable: true               # 可选：false 则用户命令中隐藏
---

# 标题
正文……（完整指令，模型加载技能时全文注入上下文）
```

### 校验规则
- `name` / `description` **缺失**，或 `name` 非 kebab-case，或调用字段值非法 → 该技能会被**跳过**并记录警告（宁可丢弃也不带病生效）。
- **只改正文**：不影响目录摘要，模型下次加载即用新内容。
- **改 name/description/whenToUse**：触发重新发现，目录摘要更新。

## 四、如何查看技能（查看已有技能）

| 方式 | 操作 | 说明 |
|------|------|------|
| **方式 1（推荐）** | 直接对模型说 **"查看技能"** 或 **"列出所有技能"** | 模型读取所有 SKILL.md 并展示全文摘要 |
| 方式 2 | 会话自动加载 | 每次会话开始时，模型上下文自动包含技能目录（名称+描述摘要）；任务匹配时自动用 `skill` 工具加载全文 |
| 方式 3 | 手动打开文件 | 资源管理器输入 `C:\Users\19781\.dsh\skills\` 即可看到所有技能目录 |
| 方式 4 | PowerShell 列出 | `Get-ChildItem "$env:USERPROFILE\.dsh\skills" -Recurse` |

## 五、如何添加/新增技能

| 方式 | 操作 | 说明 |
|------|------|------|
| **方式 1（推荐）** | 直接告诉模型：**"添加技能：xxx"** 或 **"把以下内容存为技能：xxx"** | 模型会提炼要点 → 生成 SKILL.md → 写入技能目录 |
| 方式 2（手动） | 自己创建文件：`C:\Users\19781\.dsh\skills\<技能名>\SKILL.md` | frontmatter 中 `name` 必须 kebab-case，如 `my-skill-name` |

**生效时机**：DSH 使用文件监视器（Chokidar）监听技能目录，新建/修改文件后很快使目录失效并重新发现——实测创建后几秒内即出现在会话技能目录中，**无需重启 DSH**。若想绝对确保，新开会话一定可见。

> 💡 **推荐关键字**（对模型说）：
> - 添加：`添加技能`、`新建技能`、`存为技能`、`把 xxx 写成技能`
> - 更新：`更新技能 xxx`、`修改技能 xxx`
> - 删除：`删除技能 xxx`、`移除技能 xxx`
> - 查看：`查看技能`、`列出技能`、`有什么技能`、`技能列表`

## 六、如何删除技能

| 方式 | 操作 | 说明 |
|------|------|------|
| **方式 1（推荐）** | 告诉模型：**"删除技能 xx"** 或 **"移除技能 xx"** | 模型删除对应目录/文件 |
| 方式 2（手动） | PowerShell 删除目录/文件 | `Remove-Item "C:\Users\19781\.dsh\skills\<技能名>" -Recurse -Force` |

删除后监视器会检测到并从技能目录中移除，新会话不再出现。

## 七、如何更新技能

直接编辑技能文件的正文或 frontmatter：
- **只改正文**：目录摘要（name/description）不变，模型下次加载即用新内容。
- **改 name/description/whenToUse**：触发重新发现，目录摘要更新。

也可以告诉模型：**"更新技能 xxx：新增/修改……"**，由模型代为编辑。

## 八、其他持久化渠道（对比）

| 渠道 | 是否自动加载 | 作用域 | 适合用途 |
|------|-------------|--------|----------|
| **技能（Skill）** | 是（按需） | 用户级/项目级 | **专业知识、操作流程、经验（首选）** |
| 工作区笔记文件 | 否 | 该工作区 | 草稿、记录，需提醒读取 |
| Persona（人格） | 是（每次会话） | 全局 | 行为偏好、通用规则 |
| Goal 工具 | 会话内 | 单会话 | 长任务进度跟踪 |
| 会话记录 sessions | 否 | 全局存档 | 历史回溯、导出 |

## 九、常见问题

**Q1：为什么让模型写技能时要弹"权限确认"？**  
技能目录（`~/.dsh/skills`）在会话工作区之外，受沙箱保护；写入需升级权限，属于正常安全机制，批准即可。

**Q2：技能建了但目录里看不到？**  
检查：
1. `name` 是否为 kebab-case（如 `my-skill` 而非 `My Skill`）
2. frontmatter 是否完整（必须有 `name` + `description`）
3. 文件是否放在正确的扫描根目录（见第二节）
4. 等待几秒或新开会话

**Q3：技能和普通"记忆"有什么区别？**  
DSH 没有独立的 "Memory 模块"。技能系统就是长期记忆的唯一实现方式。普通对话只保留在当前会话与 sessions 存档中，不会自动变成技能。

**Q4：模型会不会自动把所有对话都存为技能？**  
**不会**。技能需要**主动创建**；普通对话只保留在当前会话与 sessions 存档中。

**Q5：为什么原来的技能叫 dsh-memory-guide？**  
早期把技能系统通俗地称为"长期记忆"，但"记忆"一词容易和普通对话记忆混淆，且 DSH 并没有独立的 Memory 模块。因此更名为 `dsh-skill-management`，更准确地反映其用途。
